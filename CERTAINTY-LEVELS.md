# Certainty Levels

A shared tagging system used across this repo — most heavily in
[`01-canon-timeline/`](01-canon-timeline) — to keep confirmed fact,
educated guessing, personal theory, and original fiction from blurring
together. Any claim can carry one of these tags. **No claim should appear
untagged in a canon-facing file.**

## The four levels

| Tag | Meaning | Allowed in canon files? |
|---|---|---|
| **`[CANON FACT]`** | Directly stated or shown in a primary source (stream/VOD/official material). Must cite a transcript source. | Yes — this is the only tag that belongs in `01-canon-timeline/`, `03-character-sheets/`, `04-relationship-sheets/`, `05-worldbuilding-factions/` without extra caveats. |
| **`[STRONG INFERENCE]`** | Not stated outright, but follows almost unavoidably from canon facts (e.g. "Character A must have known X, because they reacted to it on stream Y"). Still not confirmed by a direct statement. | Only with the tag visibly attached — never presented as a bare fact. |
| **`[MY INTERPRETATION]`** | Your personal read, theory, or speculation. Reasonable, but genuinely uncertain — a different person could disagree. | Only with the tag visibly attached; belongs primarily in [`06-interpretations-theories/`](06-interpretations-theories), but may appear inline elsewhere (e.g. a timeline event's "unresolved questions") if tagged. |
| **`[FIC ADDITION]`** | Invented for original fiction. Not a claim about canon at all — it's a deliberate creative choice. | Never in a canon file. Belongs in `07-story-outlines/`, `08-prose-drafts/`, `09-finished-stories/`. |

## Rules

1. **Tag every claim, not just the file.** A single event or sheet can
   legitimately mix tags — e.g. what happened is `[CANON FACT]`, why it
   might have happened is `[MY INTERPRETATION]`. Tag at the sentence or
   bullet level, not just once at the top.
2. **Interpretation never gets rounded up to fact.** If you're not 100%
   sure it was stated directly on stream, it isn't `[CANON FACT]` — use
   `[STRONG INFERENCE]` or `[MY INTERPRETATION]` instead, and cite what
   it's inferred from.
3. **`[FIC ADDITION]` is a different axis, not a "lowest confidence"
   level.** It's not about how sure you are — it's original invention for
   a story. Keep it out of anything meant to describe canon.
4. **A file's overall "Certainty level" field (where present) is a
   summary, not a substitute** for tagging individual claims inside it.
   A file can be summarized as "Mostly confirmed" while still containing
   a `[MY INTERPRETATION]`-tagged aside — the summary just shouldn't hide
   that the aside exists.

See [PROJECT_RULES.md](PROJECT_RULES.md) for how this fits into the
broader canon/interpretation/fiction split.
